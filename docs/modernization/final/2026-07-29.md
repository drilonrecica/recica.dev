# Modernization Audit — 2026-07-29

This report records the repository state after the modernization implementation.
It separates locally verified repository behavior from production and
infrastructure work that still requires the owner.

## Delivered architecture

| Publication | Product direction              | Build                   | Production runtime                      |
| ----------- | ------------------------------ | ----------------------- | --------------------------------------- |
| Recica      | Dark Technical Dossier         | Astro 7 static `dist/`  | Coolify Nixpacks static site            |
| Tools       | Dark/light Utility Switchboard | Strict static SvelteKit | Unprivileged Nginx; no Node application |
| Labs        | Light Research Notebook        | Strict static SvelteKit | Unprivileged Nginx; no Node application |

The publications retain independent package manifests, pnpm lockfiles, build
contexts, deployment resources, and product responsibilities. No root workspace
or shared UI library was introduced.

## Main outcomes

- Node 24 and `pnpm@11.18.0` are pinned across all three applications.
- Tools and Labs use `@sveltejs/adapter-static` with strict prerendering and no
  SPA fallback.
- Fixed production origins drive canonicals, structured data, robots, and
  sitemaps; previews remain noindex.
- Hash-based SvelteKit CSP, static response headers, real 404 behavior, and
  source-map checks are enforced.
- Recica publishes a dossier homepage, substantive About page, and three
  canonical case-study documents while preserving its public anchors.
- Tools publishes 24 numbered utilities with per-tool content, references,
  consistent UTF-8 input limits, local-processing disclosures, and a privacy
  page.
- Tools' native service worker caches only known same-origin assets and public
  documents. It excludes non-GET, third-party, query-string, health/error, and
  user-generated data.
- Labs publishes one complete study and one clearly non-routable in-progress
  note. Parental Gate remains fully interactive.
- Four SHA-pinned GitHub Actions workflows, Dependabot, bundle budgets,
  Lighthouse assertions, accessibility tests, dependency audits, secret
  scanning, and scheduled cross-browser jobs are defined.
